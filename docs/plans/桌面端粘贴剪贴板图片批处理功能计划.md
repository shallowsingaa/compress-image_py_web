# 网页桌面端剪贴板图片批处理计划

Status: implemented for the browser UI on 2026-05-16. The separate CLI Windows clipboard path lives in `main.py --clipboard` and `clipboard_io.py`.

## Summary

- 在网页版的桌面端新增 `Ctrl+V`/粘贴图片入口：读取剪贴板中的一张或多张图片，直接用当前页面的统一压缩参数提交到现有 `/api/jobs`。
- 任务完成后优先自动复制所有成功压缩的结果到剪贴板；若浏览器权限、HTTPS、安全上下文或系统多项剪贴板限制导致失败，则显示“一键复制结果”按钮回退。
- 不改后端压缩逻辑、不改 API 字段、不破坏现有选择文件、拖拽、下载单张、逐个下载、下载 ZIP 流程。

## Key Changes

- 前端在 `web/src/main.tsx` 增加桌面剪贴板工作流：
  - 只在桌面体验启用提示和全局 paste 监听，忽略输入框、下拉框、可编辑区域内的粘贴。
  - 从 `ClipboardEvent.clipboardData` 提取 `image/*` 文件；必要时提供手动“从剪贴板读取”按钮作为兼容入口。
  - 粘贴图片后开启一个新的剪贴板批次：清空旧任务展示，提交本次粘贴到的图片；如果任务正在提交/处理中，则拒绝新粘贴并给出中文提示。
- 结果复制逻辑：
  - job 完成后，拉取每个 `done` 文件的现有下载地址，构造 `ClipboardItem[]` 写入 `navigator.clipboard.write()`。
  - 优先使用输出文件真实 MIME；若浏览器不支持该 MIME，则把图像转换为 `image/png` 后复制。
  - 多图复制按浏览器/操作系统能力 best-effort；若系统只接受第一项，界面明确提示“系统可能只接收了第一张”，保留下载入口。
- UI 保持现有设计语言：
  - 在拖拽上传区的小字中加入“桌面端可粘贴截图/图片”的轻量提示。
  - 在结果区下载按钮附近增加紧凑的剪贴板状态行和“一键复制结果”按钮，沿用当前色彩、8px 圆角、lucide 图标和中文文案。
- 错误与性能：
  - 处理无图片、权限拒绝、非 HTTPS/非安全上下文、压缩部分失败、复制失败、结果过大转换失败。
  - 不使用 base64 批量塞内存；结果以 Blob 流程处理，限制并发拉取/转换，转换后释放临时资源。

## Interfaces

- 后端 API 不新增路由，不改 `Job`/`JobFile` 响应字段。
- 前端新增本地状态类型，例如 `ClipboardState`/`ClipboardCopyStatus`，只影响 UI 状态和提示。
- 文档仅在 README 或 docs 已列功能清单时补充一句桌面剪贴板能力；`docs/api.md` 不需要改，因为 API 合约不变。

## Test Plan

- 运行 `cmd /c npm run build` 验证 TypeScript 和 Vite 构建。
- 桌面 Chrome/Edge 手动验证：
  - 粘贴 1 张截图后自动压缩并复制，能粘贴到微信/QQ/文档或浏览器测试区。
  - 粘贴多张图片后只提交本批图片，成功项自动复制；失败项显示原有错误。
  - 正在处理时再次粘贴会被阻止并显示友好提示。
  - 在参数输入框内粘贴数字不会触发图片处理。
  - 禁用剪贴板权限或 HTTP 非安全环境时，显示“一键复制结果”按钮和下载回退。
- 回归现有上传、拖拽、单张下载、逐个下载、ZIP 下载。

## Assumptions

- 采用“自动优先 + 按钮回退”兼容策略。
- 生产环境需要 HTTPS 或同等安全上下文；本地 `localhost`/`127.0.0.1` 用于开发验证。
- Clipboard API 的多项写入受系统限制：即使传入多个 `ClipboardItem`，底层系统可能只写入第一项；实现会尽力复制全部并把限制反馈给用户。参考：[MDN Clipboard.write](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/write)、[MDN Clipboard.read](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/read)、[MDN ClipboardEvent.clipboardData](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardEvent/clipboardData)、[W3C Clipboard API](https://w3c.github.io/clipboard-apis/#dom-clipboard-write)。
